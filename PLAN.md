# AqylRoute AI — текущий план

Обновлено 30.09.2026. Этот план отражает новое решение: в продукте остаётся только родитель. Предыдущий план с куратором сохранён в [PLAN-legacy.md](PLAN-legacy.md). Требования исходной задачи КМУ в [Archcore](.archcore/kmu-task-requirements.rule.md) всё ещё описывают две роли; текущая версия от них отступает.

## Сейчас

- Вход через Supabase Auth без выбора роли. Один демо-аккаунт родителя.
- Dashboard `/parent`: слева вертикальный маршрут, справа визуализация работы агента.
- Демо-сценарий показывает изучение контекста семьи, поиск программы, сравнение мест и выбор времени. Все места и даты синтетические.
- Родитель выбирает слот; результат появляется в маршруте. Выбор хранится только в памяти страницы и не создаёт реальную запись.
- Интерфейс собран из shadcn/ui, Tailwind и текущих токенов проекта.
- Серверная конфигурация OpenAI сохранена для следующего этапа; нынешний сценарий её не вызывает.
- Интервью сохраняет ответы в Supabase. Завершение пока не создаёт Case Plan.
- Из удалённой ветки добавлены схема CasePlan, справочник услуг и таблицы кейсов. Текущий родительский интерфейс их пока не использует; `profiles.role` остаётся в базе из-за проверки ролей в `cases`.

## Следующие этапы

1. Определить контракт реального маршрута и событий агента: источники, доказательства, статусы, выбор родителя.
2. Подключить серверные инструменты поиска программ, центров и слотов через Next.js Route Handlers.
3. Подключить OpenAI для выбора следующего действия в заданных границах и проверки результата на сервере.
4. Сохранять подтверждённый выбор, статусы шагов и сроки в Supabase.
5. Добавить ошибки, просрочку и повторный поиск; обновить сценарии демонстрации.

## Проверка

- `pnpm build` и `pnpm lint`.
- Вход родителя, просмотр timeline, выбор времени и обновление шага без перезагрузки.
- На экране явно указано, что поиск, центры и запись синтетические.
- Миграции `0003_cases_plans_catalog.sql` и `0004_parent_interview.sql` применяются по порядку; `profiles.role` остаётся для схемы кейсов.

## Goal

Сравнить варианты стека для хакатон-MVP внутри рамок КМУ и назвать, что решает выбор. Отдельно записаны рекомендация материала @rnd.md и оценка по данным репозитория.

## Questions

1. Какие рамки стека задаёт КМУ?
2. Backend: FastAPI или Next.js Route Handlers?
3. База данных: Supabase или SQLite?
4. Какая модель данных нужна и как менять статус шага?
5. Какую пару выбрать для хакатон-MVP?

## Approach

Метод: разбор разделов материала «Что хранить в базе» и «Рекомендуемый стек», сравнение с правилом КМУ и с кодом репозитория. Документацию Next.js, FastAPI, Supabase и OpenAI не проверял; такие утверждения помечены «по материалу, не проверено». Данных о составе команды, сроке хакатона и хостинге нет.

### Inputs

- @rnd.md — материал «AqylRoute AI — проект решения веб-MVP», предоставлен пользователем 30.09.2026; автор и первичные источники неизвестны.
- Правило «Требования задачи КМУ к MVP AqylRoute» (accepted), пункт 11.
- @package.json — Next.js 16.3.7, React 19.2.8, pnpm 10.22.0, зависимости `@supabase/ssr` и `@supabase/supabase-js`; пакета OpenAI SDK нет.
- @src/lib/supabase/server.ts и @src/proxy.ts — серверный клиент Supabase, чтение роли из `profiles`, обновление сессии; коммит ed7edff создал приложение.

## Findings

1. Вопрос 1. Пункт 11 правила КМУ: Next.js, FastAPI или Node.js, OpenAI Structured Outputs, SQLite или Supabase. Два синтетических кейса и публичная ссылка идут отдельными пунктами. Next.js и OpenAI Structured Outputs обязательны; backend и база выбираются из пар.
2. Вопрос 2. Материал рекомендует Next.js App Router + FastAPI + Supabase. Довод за FastAPI по материалу, не проверено: Pydantic даёт второй слой типизации запросов и ответов, а отдельный API-слой нагляднее для жюри. Тот же материал допускает для короткого хакатона Next.js Route Handlers на Node.js. Компромиссы по моей оценке: FastAPI добавляет второй язык, второй сервис для деплоя, передачу токена Supabase между сервисами и дубль схем (TypeScript у фронтенда, Pydantic у backend); Route Handlers держат один язык и один деплой, но слой менее заметен. [assumption] Разница во времени сборки заметна для срока хакатона, но измерений нет.
3. Вопрос 3. Материал выбирает Supabase (Auth + Postgres RLS) вместо SQLite. Довод по материалу, не проверено: RLS ограничивает строки по роли, а приёмочная проверка «родитель A не получает case B» опирается на RLS. SQLite проще по инфраструктуре, но не даёт RLS и готовой аутентификации; права придётся проверять в коде приложения. [assumption] На serverless-хостинге файл SQLite не сохраняется между запусками; хостинг не назван. Косвенный довод из репозитория: Supabase-зависимости и клиент уже подключены (@package.json, @src/lib/supabase/server.ts).
4. Вопрос 4. Модель данных материала: `profiles` (роль parent или curator), `cases`, `interview_sessions` (`answers_json`), `case_plans` (`plan_json`, `schema_version`, `catalog_version`, `revision`, `approved_at`, `approved_by`), `case_events` (журнал аудита), `service_catalog` (`definition_json`, `catalog_version`, `effective_from`, `effective_to`). Каноническим объектом служит `case_plans.plan_json`, что выполняет пункт 3 правила КМУ. Смена статуса пишет JSON и событие одной транзакцией. [assumption] Клиент `supabase-js` не выполняет многооператорные транзакции; для этого нужна функция Postgres (RPC), а FastAPI с прямым подключением к Postgres может открыть транзакцию сам.
5. Вопрос 5. Рекомендация материала: Next.js + FastAPI + Supabase. Моя оценка по репозиторию: пара Next.js Route Handlers + Supabase ближе к текущему коду, потому что Supabase и Next.js уже подключены, а второго сервиса нет. [assumption] Route Handlers на Node.js подпадают под «Node.js» пункта 11; подтверждение у организаторов не получено. Решение зависит от четырёх фактов: есть ли в команде человек, готовый вести FastAPI; сколько времени до демо; ценит ли жюри отдельный API-слой; где будет размещена публичная ссылка.
6. Состояние репозитория: @src/app/page.tsx остаётся стартовой страницей; Route Handlers, OpenAI SDK и таблицы Supabase ещё не созданы. Значит выбор backend не требует переделки готового кода.

## Recommendation

**Refine.** Supabase принять как базу: довод по материалу (RLS для приёмочной проверки) подтверждён зависимостями репозитория. Для backend склоняюсь к Next.js Route Handlers, но окончательный выбор откладываю до ответов на четыре вопроса Finding 5; без данных о команде и сроке решение остаётся гипотезой. Рекомендация материала (FastAPI) сохраняется как вариант, если ответы дадут Python-компетенцию и запас времени.

## Goal

Определить, что решает модель при построении Case Plan и что остаётся за backend и справочником, по материалу @rnd.md. Вывод нужен, чтобы выполнить пункты 5, 6 и 7 правила КМУ: действия только из справочника, объяснение шага, никаких диагнозов.

## Questions

1. Что именно возвращает модель и что достраивает backend?
2. Какие проверки стоят между ответом модели и планом на утверждении куратора?
3. Какие данные уходят в модель?
4. Почему модель не генерирует весь Case Plan?

## Approach

Метод: разбор разделов материала «Единый контракт Case Plan» и «AI не должен быть источником нормативной истины», сопоставление с правилом КМУ. Код не писался, поведение OpenAI Structured Outputs не проверялось. Нормативные и технические утверждения материала помечены «по материалу, не проверено».

### Inputs

- @rnd.md — материал «AqylRoute AI — проект решения веб-MVP», предоставлен пользователем 30.09.2026; автор и первичные источники неизвестны.
- Правило «Требования задачи КМУ к MVP AqylRoute» (accepted), пункты 4–7 и 3.

## Findings

1. Вопрос 1. Модель возвращает только `selected_actions[]` из `action_id`, `priority` и `rationale`, а для интервью — `next_question_id`. Текст вопроса берётся из локального банка. Поля `title`, `agency`, `responsible`, `documents` и нормативный `deadline` приходят из service catalog, а не из модели. `action_id` задан как enum всех action templates. Это по материалу, не проверено на практике.
2. Вопрос 2. Порядок в материале: `InterviewState` → rules engine (список допустимых `allowed_actions`) → OpenAI Structured Output в strict-режиме → backend validator → hydration из справочника → Canonical CasePlan v1 → `pending_curator`. Модель получает только допустимое множество. Validator по материалу проверяет: неизвестный `action_id` (ответ отклоняется), prerequisites (backend добавляет зависимость или отклоняет генерацию), сроки (`validate_deadlines`), отсутствие диагностических формулировок (генерация отклоняется или `rationale` создаётся заново).
3. Вопрос 3. По материалу, в OpenAI уходит обезличенный контекст: `age_band`, `region_code`, `education_stage`, флаги вроде `has_pmpk` и `receives_school_support`, `parent_goals`. Не уходят: ФИО, ИИН, адрес, номер школы, диагноз, медицинская карта, скан заключения. Правовое основание этой границы описано в отдельном документе о данных.
4. Вопрос 4. Причина отказа от полной генерации плана: по материалу, документация OpenAI отмечает, что Structured Outputs гарантируют соответствие схеме, но не устраняют содержательные ошибки в корректном JSON, не проверено. Ошибка «схема верна, услуга выдумана» проходит schema-валидацию. Выбор из enum и проверка на backend закрывают такой сбой. Второй довод: поле `diagnosis` в схеме не создаётся вообще, даже как `null`.
5. Условие применимости осложняет rules engine. Действия `MSE_PREPARE`, `MSE_COMPLETE` и `SOC_HOME_APPLY` по материалу требуют направления или документально подтверждённого eligibility-флага, а не вывода из свободного текста родителя. [assumption] Источником флага служит подтверждение куратора; материал источник не называет.
6. Материал не задаёт число повторных попыток при отклонённой генерации и поведение при полном отказе. [assumption] Нужен предел попыток и запасной путь: пустой черновик для ручной сборки куратором.

Граница по материалу (полные строки его таблицы):

| Может AI | Не может AI |
|---|---|
| выбрать `action_id` | придумать новую услугу |
| расставить приоритеты | назначить официальный срок |
| объяснить выбор | придумать документы |
| выбрать следующий вопрос | определить диагноз |
| выявить пропущенный шаг | определить право на инвалидность |
| суммировать ответы | самостоятельно утвердить план |

## Recommendation

**Proceed.** Взять конвейер «rules engine → strict Structured Output → validator → hydration» как основу генерации плана. Основание: Findings 1, 2 и 4 закрывают пункты 5 и 7 правила КМУ структурно, а не через system prompt; Finding 3 ограничивает данные. До реализации закрыть Findings 5 и 6: источник eligibility-флага и порядок повторных попыток. Поведение OpenAI и нормативные утверждения проверить отдельно.

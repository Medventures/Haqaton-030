## Rule

Применяется ко всему коду MVP: `src/**` (Next.js), серверный слой API, схемы данных и промпты AI.

1. WHEN изменение затрагивает поток MVP, the команда MUST сохранять цепочку: AI-интервью → Case Plan → контроль сроков → эскалация просрочки.
2. WHEN родитель проходит AI-интервью, the система MUST задать от 8 до 12 адаптивных вопросов.
3. WHEN сервер сохраняет Case Plan, the сервер MUST хранить его как одну стабильную JSON-структуру.
4. WHEN сервер собирает шаг Case Plan, the сервер MUST заполнить приоритет, ответственного, срок, документы и статус.
5. WHEN AI добавляет действие в Case Plan, the AI MUST выбрать его только из справочника услуг.
6. WHEN AI добавляет шаг, the AI MUST дать объяснение этого шага для семьи.
7. WHEN AI формирует вопрос, план или объяснение, the AI MUST NOT ставить или называть диагноз.
8. WHEN план ещё не подтверждён куратором, the интерфейс родителя MUST NOT показывать этот план.
9. WHEN куратор или родитель меняет статус шага, the сервер MUST сохранить статус так, чтобы он сохранялся после перезагрузки.
10. WHEN срок шага прошёл и шаг не завершён, the интерфейс MUST показать просрочку родителю и куратору.
11. WHEN команда выбирает стек, the команда MUST использовать Next.js, FastAPI или Node.js, OpenAI Structured Outputs, SQLite или Supabase.
12. WHEN команда готовит демонстрацию, the команда MUST показать два синтетических кейса по публичной ссылке.
13. WHEN пользователь работает в MVP, the система MUST различать только две роли: родитель и куратор.

## Rationale

Это постановка задачи от КМУ (Карагандинский медицинский университет), принята как исходное условие хакатона. Текст задачи без изменений:

> Проблема. Родители детей с РАС теряются между медициной, образованием и соцзащитой и повторно собирают документы. Специалисты при этом не видят полный маршрут ребёнка. Потенциально это затягивает получение помощи ребенком.
>
> Задача. Нужен веб-MVP по публичной ссылке: AI-интервью (8–12 адаптивных вопросов) → межведомственный Case Plan → контроль сроков → эскалация просрочки.
> MVP: стабильный Case Plan в одной JSON-структуре, без диагнозов, с сохранением статусов и показом просрочки.
>
> Case Plan: у каждого шага есть приоритет, ответственный, срок, документы и статус. AI берёт действия только из справочника услуг, объясняет каждый шаг и не ставит диагноз.
>
> Роли: родитель и куратор. Куратор подтверждает план до показа семье, ведёт статусы и видит просрочки.
>
> Требования к технологическому стеку: Next.js, FastAPI/Node.js, OpenAI structured outputs, SQLite/Supabase; два синтетических кейса.

## Examples

### Good

```json
{
  "action_id": "PMPK_APPLY",
  "priority": "high",
  "responsible": { "role": "parent", "organization_type": "PMPK" },
  "deadline": { "kind": "internal_target", "due_at": "2026-10-03T23:59:59+05:00" },
  "documents": [{ "document_id": "CHILD_ID", "requirement": "required", "status": "available" }],
  "status": "ready",
  "explanation": "Этот шаг нужен для оценки образовательных потребностей."
}
```

### Bad

```json
{
  "title": "Оформить инвалидность по аутизму",
  "diagnosis": "РАС",
  "explanation": "У ребёнка признаки аутизма"
}
```

Здесь действие придумано моделью, а не взято из справочника. У шага нет приоритета, ответственного, срока, документов и статуса. В тексте есть диагноз.

## Enforcement

Ручная проверка на ревью и по чек-листу приёмки перед демонстрацией. Автоматических проверок пока нет: они появятся вместе с валидатором Case Plan на сервере.

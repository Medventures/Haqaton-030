## Purpose & Scope

Контракт вкладки «Заключение ПМПК»: загрузка, AI-разбор, проверка родителем и применение к маршруту по @.archcore/digital-child-route.prd.md (экран 2 демо). Реализован один документ ПМПК на родителя; остальные типы документов распознаются, но маршрут не меняют. Решения по хранению и отправке в модель: @.archcore/pmpk-document-storage.adr.md и @.archcore/personal-data-and-access.rnd.md. Код: @src/domain/pmpk.ts, @src/server/pmpk-api.ts, @src/server/pmpk-openai.ts, @src/app/parent/pmpk-panel.tsx, миграции @supabase/migrations/202609300002_pmpk_documents.sql и @supabase/migrations/202609300003_pmpk_route_inputs.sql. Подбор центров и запись — @.archcore/center-matching-booking.spec.md, вне этой реализации.

## Surface

- Вход: PNG, JPEG или PDF до 10 МБ, явное согласие родителя на хранение и отправку в OpenAI.
- API (cookies Supabase или Bearer): `GET /api/pmpk` (текущий документ), `POST /api/pmpk` (регистрация, адрес загрузки), `GET|DELETE /api/pmpk/{id}`, `POST /api/pmpk/{id}/parse` (старт разбора), `POST /api/pmpk/{id}/retry` (повтор после сбоя), `POST /api/pmpk/{id}/confirm`, `POST /api/interview/reset`. Описание: @docs/api.md.
- Файл идёт из браузера напрямую в закрытый bucket `pmpk-documents` по пути `{parent_id}/{document_id}`; функция API файл не принимает (лимит тела запроса на Vercel).
- Статусы: `pending_upload`, `parsing`, `needs_review`, `confirmed`, `failed`.
- Поля разбора и подтверждения: `document_type` (`PMPK_CONCLUSION`, `SPECIALIST_CONCLUSION`, `INDIVIDUAL_PROGRAM`, `IPR`, `REHAB_CENTER_PLAN`, `MEDICAL_EXTRACT`, `TEST_RESULT`, `OTHER`), `issued_on`, `consultation_on`, `issuer`, `next_route` (`KPPK`, `OTHER`), `specialists[]`, `support_format`, `sessions_per_week`. Разбор дополнительно хранит `source_quotes[]` и `dropped_fields[]`.
- Диагноз отдельным полем не извлекается.

## Normative Behavior

1. WHEN родитель выбирает файл, the интерфейс MUST показать предпросмотр и отправить файл только после явного согласия.
2. WHEN родитель начинает загрузку, the система MUST зарегистрировать документ, сохранить оригинал в закрытом bucket и хранить путь объекта, а не публичный адрес.
3. WHEN оригинал сохранён, the сервер MUST определить тип файла по содержимому, а не по заявленному типу, и только потом отправлять его в модель.
4. WHEN модель отвечает, the сервер MUST принять ответ только по strict-схеме и не вызывать модель повторно без действия родителя.
5. The AI-куратор MUST NOT добавлять специалиста, формат или частоту, которых нет в документе; `sessions_per_week` MUST быть `null`, если частота не указана.
6. IF значение `next_route`, `specialists`, `support_format` или `sessions_per_week` пришло без подтверждающей цитаты, THEN the сервер MUST очистить его и указать в `dropped_fields`.
7. IF дата из ответа модели невозможна, вне диапазона 2000-01-01…завтра или консультация позже выдачи, THEN the сервер MUST очистить дату и попросить родителя проверить её.
8. The сервер MUST заменять в цитатах длинные цифровые последовательности (похожие на ИИН) на «•••» и MUST NOT восстанавливать скрытые ФИО и ИИН.
9. WHEN разбор завершён, the интерфейс MUST показать поля рядом со ссылкой на оригинал и дать родителю исправить любое поле до подтверждения.
10. WHEN родитель подтверждает разбор, the сервер MUST принять только поля из Surface для той ревизии разбора, которую родитель видел, и сохранить `confirmed_json` и `confirmed_at`. Это и есть запись в историю: отдельной таблицы событий нет.
11. WHEN подтверждён документ типа `PMPK_CONCLUSION` хотя бы с одной датой, the система MUST считать факт `pmpk_conclusion_confirmed` выполненным и убрать этапы ПМПК из маршрута.
12. The шаг подачи документов в КППК (`EDU_REHAB_APPLY`) MUST разблокироваться только если подтверждённое `next_route` равно `KPPK`; при `OTHER` или отсутствии направления шаг остаётся заблокированным с пояснением.
12a. WHEN сервер генерирует маршрут, the сервер MUST передать модели подтверждённые `next_route`, `specialists` и `support_format` (коды, без дат, организации и цитат).
12b. The входы маршрута (`parent_facts()` в базе, `routeInputsFromDocument` в коде) MUST содержать идентификатор документа и `confirmed_revision`; каждое подтверждение с изменёнными полями MUST увеличивать `confirmed_revision`, повторное подтверждение тех же полей — нет.
12c. WHEN подтверждённые поля изменены или документ удалён, the сервер MUST считать сохранённый маршрут устаревшим, а сохранение ответа OpenAI MUST отклоняться (`facts_changed`), если входы изменились во время генерации. Интерфейс после подтверждения запускает новую генерацию.
13. The AI-куратор MUST NOT создавать программу занятий по заключению ПМПК; программу создаёт специалист КППК.
14. WHERE документ — анализ или выписка, the AI-куратор MUST только разложить данные по дате, без медицинских выводов; такие документы маршрут не меняют.
15. WHEN родитель сбрасывает данные (`POST /api/interview/reset`), the сервер MUST удалить ответы анкеты, документ и результаты разбора, оригинал в Storage и сохранённый маршрут, и MUST вернуть успех только после удаления файла.
16. WHEN разбор ещё идёт, а документ удалён или сброшен, the сервер MUST отбросить поздний ответ модели и MUST NOT восстанавливать данные.

## Constraints & Invariants

- До подтверждения родителем маршрут не меняется.
- Один документ на родителя. Чтение — только владельцу (RLS); запись — только через RPC service_role. Браузер может загрузить файл лишь в путь своего зарегистрированного документа, который ждёт файл.
- Разбор запускает `claim` с идентификатором генерации, ревизией и lease 150 с; сохранение результата проверяет документ, генерацию и lease. Лимит: одна попытка в 30 секунд и 10 в UTC-день на родителя (счётчик не сбрасывается удалением документа).
- Хранение в OpenAI: `store: false`; файл передаётся содержимым запроса, а не через Files API.
- Storage и Postgres не делят транзакцию: долг на удаление записывается в `storage_deletion_queue` в той же транзакции, что и удаление строк. Сервер берёт конкретные задания, удаляет их объекты и лишние объекты в папке родителя (кроме файлов существующих документов), и только после успеха Storage убирает из очереди именно взятые пути. Задания, добавленные во время очистки, и задания после ошибки Storage остаются для следующего прохода.

## Failure Behavior

1. IF файл не PDF, PNG или JPEG, THEN the сервер MUST пометить разбор `failed` (`invalid_file`); родитель удаляет документ и загружает другой.
2. IF файл не был загружен, THEN the статус MUST стать `failed` (`file_missing`) без вызова модели.
3. IF модель недоступна, отказала или ответила вне схемы, THEN the оригинал MUST остаться сохранённым, а родитель MUST увидеть причину и кнопку «Повторить разбор». Интерфейс после ошибки `/parse` MUST перечитать документ и показать серверный статус (`failed` — повтор, `parsing` — ожидание); если состояние прочитать не удалось, он MUST сообщить об этом, не утверждая, что файл не загружен.
4. IF конфигурация OpenAI отсутствует, THEN the разбор MUST завершиться `failed` (`configuration_missing`), файл остаётся.
5. IF lease истекла, THEN the GET MUST показать `failed` (`generation_expired`) с возможностью повтора.
6. IF документ не заключение ПМПК, THEN the подтверждение MUST быть отклонено (`not_pmpk_conclusion`), маршрут не меняется.
7. IF удаление файла не завершилось, THEN the сервер MUST вернуть ошибку `cleanup_incomplete`, оставить долг в очереди, а повтор действия MUST его завершить.

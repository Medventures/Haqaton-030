## Context
30.09.2026 пользователь попросил связать сайт, OpenAI API и Supabase и предоставить рабочий API.
@src/app/parent/parent-journey.tsx показывал фиксированные центры, слоты и ложное подтверждение отправки заявки; серверного запроса модели не было.
Текущий продукт использует один родительский поток, поэтому старые таблицы CasePlan с обязательным куратором не подходят для этого подключения.

## Decision
Используем POST/GET /api/agent/route, OpenAI Responses API со strict Structured Outputs и новую таблицу parent_ai_routes для предварительного маршрута родителя.

## Alternatives Considered
- Старый CasePlan с назначением куратора: отклонён для этой интеграции, поскольку текущий пользовательский поток исключает роль куратора.
- Вызов OpenAI из браузера: отклонён, поскольку раскрывает ключ и не обеспечивает проверку источника ответов и сохранения.
- Свободная генерация центров и дат: отклонена, поскольку подтверждённых источников расписания и внешней записи пока нет.

## Consequences
Положительные: маршрут сохраняется в Supabase и читается только владельцем; повторный POST для тех же ответов переиспользует сохранённый результат.
Издержки: требуется одна добавочная миграция; лимиты вызовов — одна попытка в минуту и двадцать за UTC-день на пользователя.
Поиск центров и внешние заявления не выполняются; интерфейс показывает предварительный маршрут с действиями из справочника.

## Superseded when
- Появляется подтверждённый контракт внешней записи с API организации.
- Пользователь возвращает обязательную проверку маршрута человеком-куратором.

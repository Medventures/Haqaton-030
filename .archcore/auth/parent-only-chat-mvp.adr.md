## Context

30.09.2026 пользователь решил убрать человека-куратора и его роль из текущей системы, убрать выбор роли при входе и поместить чат для родителя на dashboard. Прежнее решение о двух ролях записано в @.archcore/auth/supabase-auth-roles.adr.md. Исходная задача КМУ в @.archcore/kmu-task-requirements.rule.md требует куратора; это осознанное расхождение текущего направления с исходной постановкой.

## Decision

- В текущем приложении одна подписанная пользовательская группа: родитель. В Supabase Auth остаётся вход по email и паролю без выбора роли. Миграция @supabase/migrations/0003_parent_only.sql удаляет роль профиля, старый placeholder статуса плана и синтетический аккаунт куратора.
- Dashboard @src/app/parent/page.tsx показывает интервью и чат. Старые страницы куратора удалены.
- @src/app/api/chat/route.ts — App Router Route Handler на Node.js. Он проверяет сессию, читает сохранённые ответы интервью, передаёт в OpenAI ограниченный контекст и отдаёт потоковый ответ через Vercel AI SDK. Интерфейс @src/app/parent/parent-chat.tsx использует AI Elements и shadcn/ui.
- Чат не создаёт Case Plan. Завершение интервью пока сохраняет ответы без статуса ожидания куратора. Новый контракт генерации плана будет отдельным решением.

## Alternatives Considered

- Оставить роль в базе, скрыв переключатель: старые проверки и состояние ожидания куратора продолжили бы влиять на систему.
- Вызвать OpenAI прямо из браузера: сервер не мог бы защищать ключ и обогащать запрос сохранёнными ответами.

## Consequences

- Старые сценарии проверки и утверждения плана куратором больше не описывают текущий продукт. Предыдущий план сохранён в @PLAN-legacy.md, текущий — @PLAN.md.
- Переписка чата пока не хранится; обновление страницы её сбрасывает. Публичный запуск потребует ограничения частоты запросов.
- Пользовательский запрос от 30.09.2026 заменяет прежнее решение о ролях, но не меняет текст исходного требования КМУ. Для соответствия тому требованию потребуется новое согласование объёма MVP.

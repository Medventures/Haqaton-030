## Subject
Чек-лист приёмки MVP AqylRoute из материала @rnd.md: проверки генерации, утверждения, статусов, просрочки и доступа. Иллюстрирует клаузы 7-10, 13, 14, 18, 20-22, 27-30 спеки контракта Case Plan. На чек-лист опираются приёмка перед демонстрацией и будущие автотесты.

## Actors
| Actor | Who they are | What they want |
|---|---|---|
| Проверяющий | участник команды, который принимает MVP по чек-листу | убедиться, что каждое ограничение работает |
| Родитель A | родитель синтетического кейса A | видеть только свой кейс и честные сроки |

## Flows
### Проверяющий
Anchors: @.archcore/case-plan-contract.spec.md
1. Проверяющий подставляет в ответ модели неизвестный `action_id`; система отклоняет ответ.
2. Проверяющий подставляет действие без prerequisite; система не присваивает шагу статус `ready`.
3. Проверяющий подставляет диагностическую фразу в объяснение; система отклоняет текст и просит новую генерацию.
4. Проверяющий завершает интервью от имени родителя; система ставит `pending_curator` и не показывает финальный план.
5. Проверяющий утверждает план от имени куратора; система создаёт неизменяемую запись approval.
6. Проверяющий меняет статус шага и перезагружает страницу; система показывает сохранённый статус.
7. Проверяющий сдвигает время за `due_at`; система ставит `is_overdue` без вызова модели.
8. Проверяющий отключает OpenAI после утверждения; система продолжает вести статусы, сроки, просрочку и роли.
Extensions: 1a. Ответ отклонён; система не создаёт план со статусом `pending_curator`.

### Родитель A
Anchors: @.archcore/case-plan-contract.spec.md
1. Родитель A открывает свой кейс до утверждения; система не показывает план.
2. Родитель A запрашивает кейс B; система отказывает в доступе.
3. Родитель A открывает шаг с внутренним ориентиром; система не называет срок нормативным.
4. Родитель A проходит интервью без направления на МСЭ; система не предлагает МСЭ как право.

### Приёмочные проверки по чек-листу
Illustrates: клаузы из колонки «Клаузы».
| Проверка | Когда | Тогда | Клаузы | notes |
|---|---|---|---|---|
| неизвестный `action_id` | модель возвращает id вне списка | backend отклоняет ответ | 7 | нет плана `pending_curator` |
| действие без prerequisite | модель выбирает `EDU_REHAB_APPLY` без ПМПК | шаг не получает `ready` | 8, 9 | материал допускает `blocked` или отказ |
| диагностическое утверждение | текст называет диагноз | генерация отклонена, текст запрошен заново | 10 | материал: rejected или regenerated |
| интервью завершено | родитель нажимает завершение | появляется `pending_curator`, не финальный план | 13 | |
| план не утверждён | родитель открывает маршрут | семья план не видит | 14 | |
| Approve | куратор нажимает «Утвердить» | неизменяемая запись approval | 18 | |
| статус изменён | обновление страницы | статус сохранён | 20 | одна транзакция с `case_events` |
| наступил `due_at` | сервер считает просрочку | `is_overdue` равен true | 21, 22 | без вызова LLM |
| родитель A и case B | запрос чужого кейса | RLS запрещает доступ | 29 | |
| нет нормативного срока | шаг с `internal_target` | UI не называет срок нормативным | 27 | |
| нет основания для МСЭ | направления на МСЭ нет | МСЭ не предложен как право | 28 | `MSE_PREPARE` не допущен |
| отключение OpenAI | план утверждён, модель недоступна | статусы, сроки, просрочка, роли работают | 30 | главный тест материала |

## Open Questions
- Материал допускает два исхода для действия без prerequisite: шаг `blocked` или отказ генерации; выбор не сделан.
- Материал даёт для диагностической фразы два исхода: отказ генерации или повторная генерация rationale.
- Нормативные сроки, использованные в проверках, взяты из материала @rnd.md и не сверены с первичными источниками.
- Проверки «первый кейс без диагностических утверждений» и «второй кейс показывает overdue» покрыты сценариями кейсов A и B.
